# LinkMAX Design System — «Тёплый мастер»

Главный документ по дизайну интерфейса LinkMAX. Если правило здесь расходится с кодом, прав этот файл: код нужно привести к нему (или изменить файл осознанно, в том же PR).

- Токены (единственный источник): `src/design-system/tokens.ts` → `npm run tokens:build` → `src/design-system/tokens.css`
- Живой каталог компонентов: маршрут `/design-system` (dev и превью Lovable)
- Решение и история: `docs/ADR/0035-app-design-system-warm-master.md`

---

## 1. Принципы

1. **Читаемо на телефоне в первую очередь.** Мастер открывает LinkMAX между клиентами, с телефона, одной рукой. Текст интерфейса — от 14 px, тап-зоны — от 44 px, главное действие — внизу экрана или в первом экране.
2. **Одно действие — один акцент.** Оранжевый (`primary`) — только у главного действия экрана и активного пункта навигации. Всё остальное — нейтральное.
3. **Цифры точные.** Деньги, время, проценты и счётчики — моноширинным шрифтом с выравниванием столбцов (`font-num`).
4. **Состояние видно формой, а не только цветом.** Статусы — это pill с точкой и словом; ошибка — текст рядом с полем.
5. **Тепло, но без украшательств.** Бумажный фон, мягкие карточки, никаких стеклянных панелей, неоновых свечений и градиентных заголовков в интерфейсе.
6. **Страница мастера принадлежит мастеру.** Интерфейс LinkMAX никогда не перекрашивает страницы, которые собрали пользователи (см. раздел 2).

## 2. Две поверхности: интерфейс и страница мастера

| | Интерфейс LinkMAX | Страница мастера |
|---|---|---|
| Где | дашборд, редактор (хром), лендинг, вход, тарифы, блог, SEO-страницы | публичная страница `/:slug`, холст редактора, превью шаблонов, запись/покупка по ссылке |
| Класс | `html.lm-app` (+ `data-app-theme="light|dark"`) | элемент `.lm-page` (его ставит `getPageThemeScope`) |
| Токены | `src/design-system/tokens.css` (генерируется) | «page base» в `src/index.css` и `src/styles/quiet-bento.css` (`:root, .lm-page`) — **заморожены** |
| Тема | светлая / тёмная / как в системе (Настройки → Аккаунт → Тема интерфейса) | тема, которую выбрал мастер (`theme_settings`) |

Правила:
- Класс `lm-app` на `<html>` ставит `AppSurface` (`src/components/layout/AppSurface.tsx`) по первому сегменту URL из `APP_FIRST_SEGMENTS` (`src/design-system/surface.ts`). Тот же список есть в скрипте в `index.html`, чтобы не было вспышки темы; тест сверяет оба списка.
- Добавляете новый маршрут интерфейса (не страницу пользователя) — добавьте его первый сегмент в оба списка.
- **Не меняйте значения page base** в `index.css`/`quiet-bento.css`: это изменит страницы всех мастеров. Тест-снапшот ловит такие изменения; если изменение намеренное — обновите снапшот и опишите в PR, как это меняет страницы.
- Компоненты, которые используются и в интерфейсе, и на страницах (`Button`, `Card`, блоки), берут отличия только из переменных. Пример: `--button-shadow`, `--button-lift`, `--button-radius-compact` — на страницах прежнее свечение и подъём, в интерфейсе плоская кнопка.

## 3. Цвет

Все цвета — HSL-триплеты **без альфы** (`20 100% 40%`). Прозрачность задаётся только в классе: `bg-primary/10`, `border-border/60`. В коде компонентов — только семантические классы Tailwind.

### Светлая тема

| Токен | Значение | Для чего |
|---|---|---|
| `background` | `60 22% 95%` бумага | фон экрана |
| `foreground` | `216 20% 8%` чернила | основной текст |
| `card` / `popover` | `0 0% 100%` | карточки, листы, меню, сайдбар |
| `muted` / `secondary` | `57 13% 91%` | утопленные поверхности: поля в покое, чипы, скелетоны, шапки таблиц |
| `muted-foreground` | `138 4% 37%` | вторичный текст, подписи (AA на фоне и на карточке) |
| `accent` | `24 90% 94%` | подсветка наведения и выбранного пункта |
| `accent-foreground` | `20 100% 30%` | текст на `accent` |
| `primary` | `20 100% 40%` (#cc4400) | главное действие, активная навигация, фокус |
| `primary-foreground` | белый | текст на `primary` |
| `destructive` | `4 76% 40%` | удаление, ошибки |
| `success` | `145 45% 33%` | оплачено, записан, подключено |
| `warning` | `34 92% 32%` | ждёт действия, лимит близко |
| `info` | `212 69% 39%` | нейтральные подсказки |
| `border` | `53 11% 84%` | разделители, границы карточек |
| `input` | `53 9% 76%` | граница полей ввода |
| `ring` | = `primary` | кольцо фокуса |

### Тёмная тема

Тёмная — самостоятельная палитра, не инверсия: фон `216 16% 8%`, карточки `216 15% 12%`, акцент светлее (`21 100% 59%`) с тёмным текстом на нём. Значения — в `tokens.ts`.

### Правила цвета

- Статусы: `success` / `warning` / `destructive` / `info`. Не используйте `emerald-*`, `amber-*`, `red-*`, `green-*` и т. п. напрямую.
- Никаких hex, `bg-white/10`, `text-white/60`, `bg-black/…` в интерфейсе. Исключения: данные тем пользователей (`lib/appearance/presets.ts`, `lib/widget-templates.ts`, `lib/avatar-frame-utils.ts`) и фирменные цвета сторонних сервисов (Kaspi, WhatsApp, Telegram) — через токен Tailwind (`kaspi`) или константу.
- Брендовые цвета для маркетинга: `brand-ink`, `brand-paper`, `brand-orange`, `brand-action`, `brand-sage`. В продуктовых экранах — только семантические.
- Количество hex и сырых палитровых классов ограничено ratchet-проверкой (`npm run quality:baseline`): новые можно добавлять только вместо старых.
- Фирменные цвета сторонних сервисов — только в `src/lib/design/brand-colors.ts` (соцсети, логотип Google, цвета QR) и в Tailwind-цветах `kaspi`, `telegram`, `whatsapp`.
- Прозрачность цвета — только ступени шкалы: 5, 10, **12, 14**, 15, 20 … 95. Tailwind 3 молча не генерирует `bg-success/13` или `bg-card/82` — элемент остаётся без фона. Тест `opacity-scale.test.ts` это ловит.
- **`dark:` в интерфейсе не пишем.** Тёмная тема интерфейса включается атрибутом `data-app-theme="dark"`, а вариант `dark:` срабатывает только от класса `.dark` (темы страниц мастеров). Токены уже тёмные — отдельные классы не нужны.
- Тонированные карточки (`bg-primary/5` на `Card`) не используем: карточка — `bg-card`, выделение — рамкой (`border-primary/30`) или плашкой статуса. Тон `bg-<status>/12` — только для статусных плашек и подсказок.
- Серый текст — `text-muted-foreground` без дополнительной прозрачности: `text-muted-foreground/60` и `opacity-60` на тексте не проходят контраст AA. Минимальный размер текста — 11 px.

### Строгие зоны

Экраны, уже переведённые на систему, проверяются жёстче: в них **0** hex, сырых палитровых классов, `white/*`/`black/*` с прозрачностью, glass-классов и `dark:`. Нарушение валит `npm run quality:baseline` с указанием файла и строки.

Сейчас строгие зоны: `src/components/dashboard-v2/` (кроме `panels/` и `screens/EditorScreen.tsx` — хром редактора переделывается на этапе 3), `crm/`, `settings/`, `billing/` (кроме `FreemiumWatermark.tsx` — рисуется на страницах мастеров), `tokens/`, `onboarding/`. Список — `STRICT_ZONES` в `scripts/quality-baseline-check.mjs`; каждый следующий перенесённый раздел добавляется туда же.

## 4. Типографика

| Роль | Шрифт | Класс |
|---|---|---|
| Интерфейс и заголовки | **Onest** (поддерживает ә ғ қ ң ө ұ ү һ і) | `font-sans`, `font-heading` |
| Цифры: цены, время, статистика | **JetBrains Mono** + табличные цифры | `font-num` |

Шкала (Tailwind `fontSize`, трекинг встроен):

| Класс | Размер | Где |
|---|---|---|
| `text-xs` | 12 px | подписи, мета, бейджи (не для основного текста) |
| `text-sm` | 14 px | основной текст интерфейса, поля, пункты меню |
| `text-base` | 16 px | текст форм на телефоне, описания |
| `text-lg` | 18 px | заголовок карточки/листа |
| `text-xl`–`text-2xl` | 20–24 px | заголовок экрана |
| `text-3xl`+ | 30 px+ | только лендинг и крупные цифры статистики |

Правила: заголовки `font-semibold` (600) или `font-bold` (700), не 800+ в интерфейсе; подписи-лейблы капсом — `text-[11px] uppercase tracking-[0.06em] text-muted-foreground`; не больше двух размеров текста в одной карточке; длинный текст — не шире 65 символов.

## 5. Отступы, сетка, радиусы, тени

- **Ритм:** 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 56 px (`gap-1…gap-14`). Внутренний отступ карточки — 16 px на телефоне, 20–24 px на десктопе. Между карточками — 12–16 px. Между секциями экрана — 24–32 px.
- **Боковой отступ экрана:** 16 px на телефоне, 24–32 px на десктопе.
- **Радиусы:** `rounded-control` 12 px (кнопки, поля, чипы-переключатели), `rounded-card` 20 px (карточки), `rounded-sheet` 28 px (нижние листы, модальные окна на телефоне), `rounded-chip` / `rounded-full` (pill-статусы, аватары). Произвольные `rounded-[..]` не используем.
- **Тени:** `shadow-sm` (карточки в покое), `shadow-md` (выпадающие меню), `shadow-lg` (листы, нижняя навигация, всплывающие окна). Тень — только у того, что лежит «над» экраном. Не добавляйте тень и рамку одновременно без причины.
- **Тап-зона:** 44×44 px минимум. Иконка-кнопка внутри плотного списка — `size="icon-sm"` (36 px) только на десктопе.

---

## 6. Движение

- Длительности: `duration-quick` (150 мс) для наведения и нажатия, `duration-base` (200–250 мс) для появления листов и меню. Анимации дольше 400 мс — только на лендинге.
- Кнопки в интерфейсе не «прыгают» при наведении; нажатие — `active:scale-[0.98]`.
- Любая декоративная анимация отключается при `prefers-reduced-motion`.

---

## 7. Иконки

- Только `lucide-react` глубоким импортом: `import Plus from 'lucide-react/dist/esm/icons/plus'` (тип — `import type { LucideIcon } from 'lucide-react'`).
- Размер: 16 px в кнопках и списках (`h-4 w-4`), 18–20 px в навигации, 24 px в пустых состояниях.
- Цвет наследуется от текста; цветные иконки — только для статусов.
- Эмодзи в интерфейсе не используем (в контенте пользователя — можно).

## 8. Компоненты

Все примитивы — `src/components/ui/*`. Не создавайте локальные копии кнопок, карточек, пустых состояний и карточек статистики.

### Button (`ui/button.tsx`)
| Вариант | Когда |
|---|---|
| `default` | одно главное действие на экране/в листе («Опубликовать», «Сохранить», «Записаться») |
| `secondary` | второе действие рядом с главным |
| `outline` | нейтральные действия в карточках, фильтры |
| `ghost` | действия в тулбарах, иконки в строках списка |
| `destructive` | необратимое удаление — всегда с подтверждением |
| `link` | переход внутри текста |

Размеры: `sm` (36–44 px), `default` (44 px), `lg` (48 px), `icon` (44 px), `icon-sm` (36 px). Состояние загрузки — проп `loading` (кнопка блокируется, показывает спиннер). Текст кнопки — глагол, описывающий результат.

### Card (`ui/card.tsx`)
`default` — контейнер контента; `interactive` — вся карточка кликабельна; `solid` — выделенная (тариф); `borderless` — группировка без поверхности. Заголовок карточки — `CardTitle` (18–20 px), описание — `CardDescription`.

### Badge (`ui/badge.tsx`) и статусы
Статус записи, заявки, страницы — `StatusBadge` (`ui/status-badge.tsx`): точка + слово, `tone="success|warning|info|destructive|neutral|accent"` или готовый `status="published|draft|…"`. `Badge`: `success` / `warning` / `info` — мягкие pill (тонированный фон, цветной текст); `default` — счётчики на акценте; `secondary` — нейтральные метки; `outline` — теги; `destructive` — ошибки. Статус заявки: «Новая» (`info` или `default`), «В работе» (`warning`), «Записан»/«Оплачено» (`success`), «Отменено» (`secondary`).

### Поля (`ui/input`, `ui/textarea`, `ui/select`, `ui/switch`)
Высота 44 px, подпись над полем (`Label`), подсказка/ошибка под полем. Ошибка говорит, что не так и как исправить («Введите номер в формате +7 7XX XXX XX XX»).

### Состояния (`ui/states`)
Единственные `EmptyState`, `LoadingState`, `ErrorState`. Пустое состояние: иконка 24 px, короткий заголовок, одна строка пояснения, одно действие («Добавить первую услугу»). Загрузка — скелетон формы будущего контента, а не спиннер на весь экран.

### Карточка статистики (`ui/stat-card.tsx`)
`<StatCard label="Визиты" value={412} icon={Eye} change={18} hint="за 7 дней" />`, `compact` — для сетки 2×2 на телефоне. Цифра — `font-num text-3xl font-semibold`, подпись — лейбл капсом, изменение — `text-success`/`text-destructive` со знаком, при наличии — спарклайн токеном `primary`.

### Тосты
Один стек — `sonner` (`import { toast } from 'sonner'`). `toast.success('Сохранено')`, `toast.error('Не удалось сохранить. Проверьте интернет и повторите.')`. Старый `useToast()` оставлен как совместимость и вызывает sonner.

### Листы и диалоги
На телефоне — нижний лист (`Sheet side="bottom"` / `Drawer`, `rounded-t-sheet`) с ручкой и кнопкой «Готово». На десктопе — боковая панель или диалог до 640 px. Модальное окно не перекрывает то, что пользователь редактирует, если можно показать панель рядом.

## 9. Паттерны экранов

- **Шапка экрана:** заголовок 20–24 px + одна главная кнопка справа (на телефоне — внизу экрана).
- **Список (заявки, записи):** строки на карточке, разделитель `border-border`, слева аватар/иконка, справа статус и время `font-num`. Тап по строке открывает детали в листе.
- **Деталь:** крупный заголовок, блок фактов (метка → значение), действия внизу.
- **Форма:** одна колонка, группы по 3–5 полей с подзаголовком, сохранение — явная кнопка или автосохранение с индикатором «Сохранено».
- **Статистика:** 2–3 карточки цифр в ряд (на телефоне — прокрутка по горизонтали или столбик), ниже — график/список.
- **Навигация:** десктоп — сайдбар на поверхности `card`, активный пункт `bg-accent text-accent-foreground`; телефон — нижняя панель из 5 пунктов, остальное — в листе «Меню».

## 10. Тексты (RU / KK / EN / UZ)

- Пишем с позиции пользователя: «Уведомления», а не «Webhook config»; «Записи клиентов», а не «Bookings».
- Кнопка называет результат: «Опубликовать», затем тост «Опубликовано».
- Все строки — через `t('ключ', 'Русский текст по умолчанию')`, ключи добавляются в ru/en/kk/uz (`npm run i18n:check`).
- Деньги: `8 000 ₸` (пробел-разделитель, знак после числа). Время: `11:00`. Дата: «6 октября», «Пн, 6 окт».
- Казахский текст длиннее русского на 10–25 %: не рассчитывайте на ширину строки.

## 11. Доступность

- Контраст текста — WCAG AA (4,5:1 для текста, 3:1 для крупного). Все пары токенов проверяет тест `src/design-system/__tests__/tokens.test.ts`.
- Видимый фокус (`focus-visible:ring-2 ring-ring`) у всего интерактивного.
- Иконка-кнопка — всегда с `aria-label`.
- Не передавайте смысл только цветом.

## 12. Можно / нельзя

| Можно | Нельзя |
|---|---|
| `bg-card border-border shadow-sm rounded-card` | `bg-white/10 border-white/10 backdrop-blur-xl` |
| `text-success`, `<Badge variant="success">` | `text-emerald-500`, `bg-green-100` |
| `font-num` для цен и счётчиков | цифры обычным шрифтом в таблицах |
| одна главная кнопка на экран | три оранжевые кнопки рядом |
| `rounded-control` / `rounded-card` | `rounded-[18px]`, `rounded-[2.5rem]` |
| тост с понятным текстом ошибки | `toast.error(String(error))` |
| `<StatusBadge tone="success">Оплачено</StatusBadge>` | `bg-emerald-500 text-white` на статусе |
| `<StatCard label value change />` | самодельная карточка цифры с `glass` |
| `EmptyState` / `ErrorState` / `LoadingState` из `@/components/ui/states` | свой вариант пустого состояния в экране |

### Перенос экрана на систему: было → стало

| Было | Стало |
|---|---|
| `emerald/green/lime/teal-*` | `success` |
| `amber/yellow/orange-*` | `warning` |
| `red/rose-*` | `destructive` |
| `blue/sky/cyan/indigo-*` | `info` |
| `violet/purple/pink/fuchsia-*`, декоративные градиенты | `primary` или `bg-accent text-accent-foreground`; в графиках — `chart-1…5` |
| `slate/gray/zinc-*` | `muted-foreground` / `border` / `muted` |
| тонированный фон `/5…/25` | `bg-<status>/12`, рамка `border-<status>/30` |
| `bg-white/5`, `bg-white/10` | `bg-muted` |
| `border-white/*` | `border-border` |
| `text-white` на `bg-<status>` | `text-<status>-foreground` |
| `glass`, `glass-card`, `shadow-glass*` | `bg-card border border-border shadow-sm` |
| `bg-card/80`, `backdrop-blur` на карточке | `bg-card` |
| `rounded-[2rem]` и т. п. | `rounded-card` / `rounded-control` / `rounded-sheet` |
| `font-black`, `font-extrabold` | `font-bold` / `font-semibold` |
| `uppercase tracking-widest` | `uppercase tracking-[0.06em]` (лейбл) |
| `tabular-nums` | `font-num` |
| `text-[8px]…text-[10px]` | `text-[11px]` минимум |
| `<CardContent className="p-4">` | `<CardContent className="p-4 sm:p-4">` — база `CardContent` задаёт `sm:p-6 sm:pt-0` |

## 13. Чек-лист ревью UI

- [ ] Только семантические токены, нет hex/`white/*`/сырой палитры (кроме разрешённых исключений), нет `dark:`.
- [ ] `npm run quality:baseline` зелёный (включая строгие зоны).
- [ ] Экран проверен на 360 px и 1280 px, в светлой и тёмной теме.
- [ ] Тап-зоны ≥ 44 px, у иконок-кнопок есть `aria-label`.

## 14. Как менять систему

- **Новый/изменённый токен:** правка в `src/design-system/tokens.ts` → `npm run tokens:build` → тесты контраста → этот файл (таблица) → каталог `/design-system` показывает его автоматически.
- **Новый компонент:** сначала проверьте, нет ли его в `src/components/ui`. Новый примитив — в `src/components/ui`, с вариантами через `cva`, описанием в разделе 8 и примером в каталоге.
- **Lovable и другие агенты:** правила в `.agent/rules/frontend.md` и `.agent/skills/design-brand/SKILL.md` ссылаются на этот файл. Перед изменением UI прочитайте DESIGN.md.
