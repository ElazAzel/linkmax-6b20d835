# LinkMAX v3.1.1 hardening plan

## Goal

Repair commit, CI, release, and deployment controls before creating the repository's first GitHub Release. Cloudflare is production; Lovable remains a GitHub-synchronized mirror. Mobile packages are validated but not published.

## Implementation

1. Isolate work on `codex/release-v3.1.1-hardening` and preserve `main`.
2. Add failing contracts for Worker assets/release identity and release workflow ordering.
3. Move SPA assets into the Worker deployment and add immutable release metadata.
4. Remove tracked environment configuration, update dependencies, and align web/mobile versions.
5. Replace duplicate deployments with strict CI, automatic staging, and approved production release workflows.
6. Add CodeQL, Dependabot, repository security guidance, pinned actions, SBOM, checksums, and provenance.
7. Verify unit, script, quality, build, browser, database, Worker, Android, and iOS gates.
8. Merge only a green PR, verify staging and Lovable, then dispatch production and create `v3.1.1` last.

## Release invariant

No production tag or GitHub Release may exist unless the exact `main` commit has passed staging, preview, Supabase, Cloudflare, production smoke, and Lovable mirror gates.
