# LinkMAX: развитие в Micro-Business OS (по присланному плану)

Принцип: не переписывать продукт и не менять стек. Идём маленькими проверяемыми шагами. Каждый шаг ничего не ломает в работающем.

## Шаг 1. Аудит без изменений (этап 0)
Создать документы в `docs/`:
- `CURRENT_ARCHITECTURE.md`: что реально есть (таблицы, правила доступа, серверные функции, вход, маршруты, переводы, мобильная оболочка, тесты).
- `DOMAIN_MODEL.md`: как сейчас связаны страница, блоки, заявки (leads), записи (bookings), товары, ивенты, заказы, аналитика. Где одно и то же лежит в разных местах (leads и zone_contacts, offers и digital_products).
- `DECISIONS.md`: принятые решения (например, Business Zones только для Business-тарифа, AI-чат без трат токенов).
- `MIGRATION_PLAN.md`: таблица «Модуль / есть / работает / что менять» с реальными цифрами из базы.
На этом шаге схему, интерфейс и зависимости не трогаем.

## Шаг 2. Единый клиент (этапы 1 и 3)
- Ввести понятие «Клиент» на уровне страницы автора. Каждая заявка, запись, покупка и регистрация на ивент привязывается к одному клиенту.
- Склейка дублей по телефону, почте, Telegram, WhatsApp (номер нормализуется).
- Источник у каждого действия: utm, страница, блок, действие.
- Старые заявки привязываются задним числом, сами данные не меняются.

## Шаг 3. История клиента (этап 2)
- В карточке заявки во «Входящих» лента событий: просмотр, клик по услуге, форма, запись, оплата, плюс выручка и источник.
- Источник событий: уже существующая аналитика и записи, новая таблица событий не нужна на первом шаге.

## Шаг 4. CRM Lite (этап 4)
- Простые стадии: Новые → Связались → Записан → Оплатил → Завершено, с переименованием.
- Заметки и задачи в карточке. Тяжёлая CRM Business Zones остаётся как есть.

## Дальше (отдельные планы после шагов 1–4)
Услуги как сущность (5), запись (6), общий checkout (7), воронка и выручка по источникам (8), единый журнал событий (9), автоматизации шаблонами (10), AI с инструментами на базе уже готовых MCP-инструментов (11), AI-аналитик (12).

## Технические детали
- Шаг 2: таблица `contacts` (page_owner_id, нормализованные phone/email/telegram/whatsapp, уникальные частичные индексы), колонка `contact_id` в leads, bookings, digital_purchases, event_registrations (nullable), SECURITY DEFINER функция `upsert_contact`, вызывается из submit-form / submit-booking / robokassa-webhook / register_for_event. GRANT и RLS по владельцу в той же миграции.
- Шаг 3: RPC `get_contact_timeline(contact_id)` собирает analytics + bookings + purchases + lead_interactions.
- Шаг 4: стадии в настройках страницы (jsonb), без новых таблиц; задачи через lead_interactions.
- Все тексты через i18n (ru, en, kk, uz), humanizer-ru.

Предлагаю утвердить шаги 1–4; остальные этапы распишу отдельно после.
